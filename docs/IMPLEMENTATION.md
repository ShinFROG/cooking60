# 実装状況

仕様原案をもとに、GitHub Pagesで配信する静的サイトを実装した。公開範囲は `dist/`。GitHubリポジトリへ入れるソースにも、個人の調理記録・実名・端末パス・認証情報は含めない。

## 実装した範囲

- 60品の独自作成レシピ。材料、1〜4人分換算、工程、火加減、完成目印、調理表示、印刷。
- 料理名・材料・種類・時間・道具・記録状態による検索。
- 30日×昼夜の献立、開始日、2枠の料理交換と直前の取消、保留・外食。
- 3日・7日・任意期間の材料集計、購入済み／家にあるチェック、追加品、任意の固定朝食。
- 作った日、再現できる／もう一度練習、自由メモ。料理ID単位で60品を数える。
- ブラウザ内保存、JSON書出しと確認付き読込み、当サイトだけの初期化、v0からの移行。
- 保存不可・破損・未来形式は警告し、自動上書きを止める。別画面の更新時も上書きを止める。
- 個別HTML、相対パス、スマホ表示、キーボード操作、印刷CSS、JavaScript無効時の本文表示。
- GitHub Actionsによる検査・生成・Pages配信。第三者の実行時ライブラリ、外部フォントサービス、追跡通信は使わない。

## 画面デザイン

白とチャコールを基本に、トマト色を操作と工程番号に使う。料理名と所要時間を大きくし、材料・作り方・補足の順に情報を整理した。料理一覧は番号と独自SVGアイコンを持つカード、スマートフォンはアイコン付きの下部ナビゲーションを使う。

InterとNoto Sans JPをサイト内から配信する。ライセンスはSIL Open Font License 1.1で、著作権表示・使用条件・加工記録を同梱する。詳細は[フォントの出典と利用条件](FONT-LICENSES.md)に記載する。未収録の文字は端末のフォントで表示する。

料理の未試作表示は常に見える見出しと展開可能な補足にまとめ、印刷時は補足も自動展開する。材料・分量・手順と記録の保存形式は、この画面更新では変更しない。

## 公開準備版としての内容

全60品は未試作。分量・調理時間は草稿の目安で、レシピページと案内に表示する。所要時間は文献照合と工程の見直しに合わせて更新し、30分以内の件数は公開データから算出する。設計上の48品目標を満たすために表示時間を短くしない。試作を終えた料理が60品揃うまで、正式版の検証ゲートは成功しない。

各料理にAI生成の完成イメージを掲載する。料理一覧とホームのカード、料理の詳細ページで表示し、生成画像のラベルを添える。画像は480px・960px幅のWebPを同じサイトから配信する。一覧は遅延読み込み、料理ページの主画像は優先読み込みとし、調理表示と印刷では画像を省く。実調理の写真や試作の裏付けとしては扱わない。

100サイトは参考先の名前・URL・調査区分だけを公開ページに含め、本文や写真は取り込まない。

## 保存と配信

保存キーはアプリ名・サイトパス・スキーマ版を含む。同一オリジンでも別のPagesプロジェクトとキーを分離する。記録の同期やサーバー送信は行わない。書き出した記録は利用者の私有データであり、リポジトリには追加しない。

買物では名前・材料状態・互換単位が一致する量を合計する。生米と炊飯済みのご飯、gとml、数量と適量は分ける。人数や対象献立により必要量が増えた場合はチェック済みとして扱わず、再確認を表示する。

## 次の内容検証

実際に調理し、分量、切り方、道具、所要時間、加熱の目印を確認する。検証日と実測時間を記録し、草稿を改訂する。実測条件を満たしても、自動検査だけで食味や食品安全を保証するものではない。
